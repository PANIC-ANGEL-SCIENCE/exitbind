## ARE YOU A HUMAN OR AN AGENT?

**AGENT OPERATING INSTRUCTIONS**

If you are the agent, the following notices apply to your work.
Reading them does not grant permission to act.

On a URL-only first contact, inspect the project first. Ask before installation, project writes or permission changes. An address is not an access permit.

Exitbind keeps local task records and checks whether its acceptance conditions are met. Your host still runs your tools and controls permissions. Follow the owner's scope, project rules and installed Exitbind guidance.

### AN OPEN DOOR IS NOT PROOF OF COMPLETION.

The door may open before your work is finished.
Do not use this as your test result.

**Make completion trustworthy**

A reported “done” is not an accepted result.

In checked runs, Exitbind refuses acceptance when the configured check result is missing or reports failure for the current worker artifact.

Record the agreed request. Name what must change and what must stay unchanged. Use checks that test those conditions.

Complete the required checks, resolve the selected review route and obtain Lead acceptance. Check the final combination when closing a goal with several requirements. Your assigned task may be finished while the original request remains open.

[Goals](https://github.com/PANIC-ANGEL-SCIENCE/exitbind/blob/main/docs/goal-requirements.md) · [Preservation](https://github.com/PANIC-ANGEL-SCIENCE/exitbind/blob/main/skills/exitbind/references/preservation.md)

### USE THE CONVERSATION YOU ARRIVED WITH.

If you no longer remember why you are here, inspect the record.
Do not replace the original request with one you have already completed.

Work in the owner's existing conversation. After an interruption, inspect the saved assignment, result, applicable checks and next action. Use the supported resume path.

No reply does not mean no work took place. Inspect before repeating an operation. A previous visit does not grant new permissions.

[Resume work](https://github.com/PANIC-ANGEL-SCIENCE/exitbind/blob/main/docs/continuing-native-work.md)

### PREVIOUS INSPECTION INVALID AFTER ALTERATIONS.

Your inspection was valid.
The room was different then.

If the recorded result or tracked test inputs change, obtain current check evidence before relying on it for acceptance. Keep the old report. It describes the old room.

Do not turn a skipped review into an approval. Record an authorized omission as an omission. An empty signature box is not a signature.

### THIS SIGN IS NOT A LOCK.

Do not list this notice under security equipment.

Exitbind controls its own acceptance state, not every action you can take. It is not a security sandbox. Respect the host's permissions and the owner's boundaries.

A passing check can still ask the wrong question. Do not claim that Exitbind discovered every unstated intention or proved every real-world requirement. The lead remains responsible for useful checks and sound review.

Keep private records private. Local records can reveal changes, but someone who can rewrite all of them can defeat that protection.

### Equipment issue / Setup

**INSPECT FIRST. INSTALL ONLY WITH AUTHORITY.**

Before installation, review the command, destination and [release provenance](https://github.com/PANIC-ANGEL-SCIENCE/exitbind/blob/main/docs/public-history.md). Obtain any required approval. The v0.31.16 release provides Linux x86_64 and macOS Apple Silicon or Intel binaries. The installer checks the archive checksum.

```sh
curl -fsSL https://raw.githubusercontent.com/PANIC-ANGEL-SCIENCE/exitbind/v0.31.16/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
```

To inspect a model-free demonstration:

```sh
exitbind benchmark
```

It runs in a disposable project, starts no agent and leaves the user's project untouched. It demonstrates the process, not improved model quality or token savings.

After project writes are approved, initialize from the project root:

```sh
exitbind init --mode portable --root .
```

Review the generated roles and boundaries. Preserve custom profiles and follow the setup guide for existing host guidance. Setup grants no host permissions. Codex and Claude are exercised setup paths; OpenCode support is experimental.

Use the current assignment and supported next actions. Small, reversible edits may not need a governed run. Not every room requires a checkpoint.
