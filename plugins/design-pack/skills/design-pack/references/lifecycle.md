# Full design lifecycle

This is a selectable path, not a mandatory paperwork sequence. Small work can combine stages in one note. Large work should retain the artifacts that prevent loss of intent. Revisit the brief when evidence changes the problem. The iterative discover/define/explore/deliver idea is consistent with the [Design Council's Double Diamond](https://www.designcouncil.org.uk/resources/the-double-diamond/); the stage contracts below are this pack's own synthesis.

| Stage | Work and artifact | Decision/evidence to advance |
| --- | --- | --- |
| Intake | Preserve the request, context, authority, deliverable, audience, constraints and existing commitments | Scope can be stated without inventing essential facts; distinguish exploration from production |
| Discovery / research | Inspect current artifacts and references, existing research and actual use; propose focused research only when useful and authorized | Evidence log separates observations from hypotheses and identifies important gaps |
| Problem definition | Identify unmet need, desired change, constraints and things to preserve | A brief states who benefits, what changes and how the result can be checked |
| Strategy | Choose priorities, positioning, medium/channel, value proposition and resource tradeoffs | Strategy serves the audience and outcome; no invented market validation |
| Concept exploration | Produce genuinely different organizing ideas at comparable fidelity | Alternatives state tradeoffs and a reasoned recommendation; material unknowns are surfaced |
| Direction selection | Record selected concept, rationale, authorization/delegation and deferred choices | Client decision or delegated choice is explicit; do not count silence as agreement |
| Prototype | Make the cheapest representative artifact that tests the largest uncertainty | Findings revise assumptions; prototype fidelity and scope of evidence are stated |
| Detailed design | Define system, content, states, materials, specifications and production constraints | Scope is buildable; cross-disciplinary dependencies and acceptance checks are assigned |
| Production / implementation | Build with the tools actually available and authorized; track spec differences | Editable artifact exists; exports and downstream handoffs preserve required information |
| Critique / validation | Check concept, task success, accessibility, medium-specific quality, rights and real context | Each required criterion has current evidence, a failure or an explicit gap; resolve material defects |
| Delivery | Package source, exports, decision summary, usage guidance, assets and known limits | Intended recipient can locate, open and use the output; formal acceptance remains with its authority |
| Maintenance / learning | Name owner, version, feedback route, known debts and update triggers | Changes preserve prior requirements; general lessons remain separate from client-specific choices |

## Scale the work

- **Refinement:** request → one-line interpretation → edit → relevant check → handoff. Avoid speculative brand strategy for a local typo or spacing fix.
- **New concept:** brief → small research set → distinct directions → representative prototype → refine → delivery.
- **Production project:** use all relevant stages, with an acceptance matrix and discipline-specific handoffs. Agree only consequential checkpoints; do not create permission barriers for already authorized routine work.

## Research without pretending

Define a question and evidence that could change the decision. Choose artifact inspection, comparative analysis, interviews, observation, prototype tasks or existing analytics according to the uncertainty. Record sample, context, limitations and consent where participant work occurs. A desk review cannot establish behavior or demand. Synthetic scenarios are test inputs, not real participants.

Use reference browsing to understand mechanisms, not to collect a wall of attractive thumbnails. Compare alternatives on the same task and intended context. Timebox exploration in proportion to the task and stop when additional options no longer change the decision.

## Change and continuity

Keep one current brief and a small decision log. On a change: capture the new requirement, determine which assumptions/specifications/artifacts are affected, estimate consequences, preserve superseded evidence as historical, then rerun impacted checks. Do not reopen unrelated approved choices.

For cross-disciplinary work, define a shared concept and semantic system, then separate production specifications. A campaign may share brand voice and visual hierarchy across packaging, website and film; its print dimensions, web breakpoints and video timings are different contracts.

## Completion

State the actual result category: concept, prototype, editable production source, validated export, or deployed/manufactured artifact. Passing a package check does not prove design quality. A mockup does not prove manufacturability; a prototype task does not prove market success. Deliver useful work at the supported level and list the exact next evidence needed for a broader claim.
