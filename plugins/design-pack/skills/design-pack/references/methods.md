# Select a method

Load only the methods needed for the current uncertainty. A small edit does not require a full lifecycle or reference search. Start from [design judgment](design-judgment.md), then choose by purpose.

| Purpose | Method |
| --- | --- |
| Short request, ambiguous feedback, decision ownership | [Briefing](briefing.md), [brief template](../templates/brief.md) |
| Find and personally inspect relevant materials | [Discovery](discovery.md), [reference analysis](reference-analysis.md) |
| Rejected direction: diagnose the concept, not only compliance | [Design judgment](design-judgment.md), [source roles](reference-roles.md), [validation](validation.md) |
| Coupled organizing ideas and executable composition | [Aesthetic construction](aesthetic-construction.md), [visual methods](visual-methods.md), [direction](direction.md) |
| Actual text, script, type assets and optical fit | [Typography](typography.md) |
| Contextual color roles and state pairings | [Color](color.md), [elements](elements.md) |
| Brand meaning through tokens, components and adaptation | [Brand system](brand-system.md), [template](../templates/brand-system.md) |
| App screen or UI mockup, from visual inputs to reviewed output | [Screen production](screen-production.md) |
| Reusable UI contracts, customization and source/docs/test parity | [Components](components.md), [component brief](../templates/component-brief.md) |
| Icon meaning, artwork, optical fit and control semantics | [Iconography](iconography.md) |
| Product flow, real states, responsive UI and refinement | [Interface](interface.md), [interface craft](interface-craft.md) |
| Background removal, subject isolation and transparent image assets | [Background removal](../../mockup-image/references/background-removal.md) |
| Image deliverable, photographic direction and placement | [Mockup Image](../../mockup-image/SKILL.md) |
| Identity, graphic/print, packaging and editorial | [Communication design](communication-design.md) |
| Information relationships and data graphics | [Diagrams](diagrams.md) |
| Objects, spaces, fashion and physical verification | [Physical design](physical-design.md) |
| Narrative, animation, video and audio | [Motion and sound](motion-sound.md) |
| 3D geometry, materials and scene evidence | [Spatial](spatial.md) |
| Explicitly selected first-attempt trial | [First pass](first-pass.md) |
| Relevant stage contracts, roles and handoffs | [Lifecycle](lifecycle.md), [roles](roles.md) |
| Actual review, accessibility and delivery | [Validation](validation.md), [handoff](../templates/handoff.md) |
| Scope owner feedback and reusable lessons | [Memory](memory.md), [project profile](../templates/project-profile.md) |
| Existing governed task integration | [Exitbind](exitbind.md) |

Methods provide production questions and decisions. They do not certify specialist practice, grant tool permissions, or establish quality through reading alone.

For hero boards and case-study sequences, use [portfolio presentation](portfolio-presentation.md) and its optional [presentation brief](../templates/presentation-brief.md). Decide the output type before applying UI-only constraints.

For mixed references, use [source roles](reference-roles.md) to separate content, craft benchmark, interface and presentation transfer.
