# Information design, diagrams and data graphics

Start with the question the reader should answer and the relationship to explain. A diagram is unnecessary if a sentence or table is clearer.

Choose the form from meaning: sequence for time/order, flow for decisions, hierarchy for containment, network for relationships, map for location, comparison for alternatives, chart for quantities. If behavior and visual form disagree, fix the model before polishing.

1. List entities, states, connections, direction, units, uncertainty and source data.
2. Distinguish actual, proposed, inferred and unavailable elements. Do not make an arrow imply a causal or authorized connection without evidence.
3. Draft the reading order and grouping. Label relationships explicitly when the meaning is not obvious.
4. Apply the active project typography and semantic colors; never silently import a reference author's palette.
5. Render at the intended reading or print size and check clipping, overlapping labels, confusing crossings and weak hierarchy.
6. Provide a text equivalent or data table for the essential message. Interactive exploration needs keyboard access and a meaningful initial view.

For charts, preserve truthful scales and units, distinguish zero from missing values, show relevant uncertainty, and avoid decorative 3D distortion. Do not manufacture numbers to make a layout impressive; label synthetic demonstration data. For dense maps, group or split only when relationships remain understandable; arbitrary node-count limits are not universal.

For deliverables, retain editable source (such as SVG or a structured scene), data/provenance, legend, reading order and export settings. A bitmap alone is insufficient when later editing is required. Test raster/export fidelity separately from the source view.
