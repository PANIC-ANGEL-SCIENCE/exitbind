# Exitbind

Exitbind is installed. It supplies local exact-result checks, review and Lead acceptance inside the current conversation. The host owns models, tools and permissions. This bootstrap is guidance, not proof of activation or compliance.

## Check applicability before setup

Classify actual effects and existing project policy before setup. For read-only questions, disposable prototypes and tiny obvious reversible edits, do not run Exitbind commands, initialize a project, or ask workflow or review-policy questions. Material or promotion consequences select governance before mutation. The Lead recommends review and the owner chooses required/omitted; reuse existing scoped decisions. Failed required activation stays an explicit blocker.

For a known Work or explicit `smw_…` locator, use the selected executable's `work detail WORK --json` directly: current profile/rules, assignment, evidence, tasks and exact action forms. Unknown project work uses `work resume --json`, then its emitted current detail route. Stale/incomplete detail needs its supported refresh/expansion before dependent action. Focus is navigation, never authority. Keep exact executable/config arguments on routes marked `sameExecutableRequired`/`sameConfigRequired`; do not guess ledger paths, flags or placeholders.

In an unconfigured project, inspect first and obtain owner consent for `exitbind init --mode portable --root .` (or preview approved facts with `exitbind setup` before `--apply`). Use `--skip-skills` when owner-selected host guidance is managed elsewhere; preserve custom or symlinked files. Init writes config/private state/profiles/project guidance, starts no model and grants no permission. Select the intended producer once with that path's `version --json` and independently verify its executable hash; equal version strings do not identify a development commit.

For new governed Work, follow applied setup's exact next argv or use `work begin WORKFLOW --goal GOAL --check-command COMMAND --review-policy required|omitted --detail`. Consume the returned complete current recipient context without another discovery read; the Lead's scope decision still precedes worker editing. A recorded start with failed delivery exposes the existing Work and a read-only recovery. If the reply was lost, use `work resume --json` with the same configuration; never repeat begin for recovery. Unmarked historical Work keeps required review and cannot revise policy. Project guidance carries the full authority rules. Product-managed Codex uses `work act WORK` for its configured pending role/check and explicit Lead decision. Host-managed native agents inspect `actionForms`: execute `beforeEditing` only when that new-permit form is present; use `currentGrant` for its exact present mutation when supplied; and complete `nextRequest` before any later mutation request. `beforeEditing` appears only when a new permit is admissible. For a lost or uncertain permit reply, retry only with the same request ID and inspect current detail/head before acting; never mint a fresh request ID merely to recover. A grant gives no host access. `replan_required` and `evidence_required` govern the next new mutation request and do not revoke a valid present grant. A validated sensor request or inert sensor result preserves it; a conservative sensor result or later semantic governor event makes it stale. Retained worker results take priority over editing and must be returned through the current recovery form first. Worker completion still requires the ready-governor state. Ordinary returns need no continuation initialization. Cross-host initialized continuation uses its own bound receive routes.

For the narrow owner-recovery form exposed by a blocked Work, require the exact
adjacent duplicate-permit events, a same-goal successor, an explicit owner
invocation attestation, and complete bounded StateRoot evidence that each
effect category is known. Unknown or held results, changed inputs/configuration,
or altered evidence keep the predecessor blocked. The protocol-2 successor
preserves all accounting and starts at `evidence_required`; it receives no old
grant, check, review, or acceptance. The frozen predecessor remains readable,
and the emitted same-goal successor command is the only admission route.

After acceptance, `effectiveAction.exists=false` remains terminal. Separate `completion.receipt.export.command` provides optional requested `work closeout WORK --export` (or `--output PATH`) using the existing Exit Path receipt and exact Work verification. Plain `work closeout WORK` and `--receipt PATH` are read-only. Current evidence may be stale despite historical acceptance; receipt verification and Work readiness remain separate from goal/publication/install completion. Repeat export reuses only a verified existing destination and never overwrites it or repeats checks/acceptance.

Report observed checks, actual role decisions, currentness/refusals and requested receipt status distinctly. `goalProgress.systemText` is product-owned. When a response carries a non-null `presentation.terminal`, that value is the terminal status block: print it on a line of its own, exactly as given, with nothing else on that line - not inside a sentence, not wrapped in emphasis. Put results and limitations in separate sentences; never reconstruct terminal wording from state or progress.

Run `exitbind host status` when asked whether setup is installed/current. An installed binary or skill alone is not an active lifecycle. For a native command or child still running, keep one handle and wait for completion or a meaningful state transition (normally 30–60 seconds). Do not start a fresh watch process or poll unchanged status at short intervals. A timeout is not a failure and never authorizes restarting. Answer an explicit human status request with the current truth.


## Consume safely and report the user outcome

Keep the returned executable/configuration/project and native execution handle. Capture process status and complete stdout/stderr before decoding; parse the declared operation's output and exact field types. Follow emitted argv without a generic --json/--config suffix: init prints prose, version --json is flat and accepts no config, permit prints JSON without a --json option, and detail uses actionForms rather than next. A parser failure after an effect requires readback, never replay. Discover unknown paths and test targets once; require an actual nonzero selected test for a coverage claim.

Consume complete current required instructions once. Use the host's protected full-response capture or native artifact when available, then display selected fields instead of duplicate context/evidence/action-form copies. Bound both each item and the total displayed batch. If the first reply was cut and cannot be parsed, recover a known Work with work next WORK --json using the same executable/config; recover a lost handle with work resume --json. Never repeat its mutation. Follow current.details for assignment, evidence, tasks and recipient independently. Current v2 sections page 4 KiB of exact content; recipient includes the full current profile, rules and selected lessons. Without full capture, retain exact hashes, encodings, offsets and all pages. Missing mandatory instructions stay missing. A failed preflight prevents dependent launch; inspect only owned handles, saved statuses, locks and boot/process identity before retrying. Timeout or PID absence after reboot cannot establish completion or replay authority.

The configured coordinator owns the selected task and user-facing result. Current recipient role/agent/assignment describe the next actor and do not assign the parent's identity. Use its current profile and purpose. Prefer the owner's displayName in human output; agent keys, native names, roles and rights remain separate. Names are configurable; a worker's label never grants Lead authority. Keep old Work configurations and custom profiles intact.

Begin the human report with the requested useful result and actual checks in the user's language. Then briefly explain a meaningful tool incident and its permitted recovery. Optional display/export failure does not reopen completed user work; required review/permission/input or uncertain effects remain unfinished outcomes. Recover saved results through public Work inspection/continuation without requiring Exitbind source, a private launcher or weaker gates. Preserve technical failures; forward only the producer's actual terminal.

Opt-in memory storage and approval do not establish activation. Check effective selection for the actual goal and delivery to the current recipient; crossContext:none remains legal storage-only policy. If activation was requested, empty required selection remains unfinished despite a successful resolve. Carry out the already authorized correction and delivery checks. Preserve the original configuration and use memory correct-policy's exact-item owner decision and predecessor-head route; select the corrected configuration for subsequent tasks and verify every intended recipient. Never self-grant missing rights, hide the predecessor in another root or edit history. Preserve expiry/revoke/source guards and old Work readers.
